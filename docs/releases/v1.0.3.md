# v1.0.3 — Noise reduction for SAST scans (`excludePaths`)

**Release date:** 2026-10-20
**Type:** MINOR (backward-compatible optional parameters)

## Why

A real re-run of `WebCodeSecurityReview` on the project's own source directory (after the
v1.0.2 directory-target fix) completed 4/4 steps, but 26 of 27 findings were known noise:
rule-definition self-matches in `lib/analyzers/sast/rules.js`, scanner implementation copy
matches (`secrets.js` PEM header text, `hash_id.js` label text), a documentation example key,
and test fixtures. The scan itself was correct; the file set was too broad.

## Added

- `excludePaths` (optional, array of strings) on:
  - `sast.scan`
  - `sast.secrets`
  - `sast.deps`
  - `sast.sbom`
- Matching is a case-insensitive substring of the normalized file path, so
  `"tests/"`, `"lib/analyzers/sast/rules.js"` and `"docs/known-issues.md"` all work
  without a glob dependency.
- Exclusion applies only to file enumeration; rules and coverage of other files are unchanged.
  The count of excluded files remains visible in the scan result (`excludedCount`).
- Test: mixed synthetic tree (rule file + test fixture + real source) proves excluded files are
  not scanned while real sources still are.

## Usage

```json
{
  "capability": "sast.scan",
  "target": "D:\\repo",
  "workspace": "D:\\work",
  "options": {
    "excludePaths": ["tests/", "lib/analyzers/sast/rules.js", "docs/known-issues.md"]
  }
}
```

## Compatibility

- Purely additive; existing calls behave exactly as v1.0.2.
- The bundle is source-linked: restart DeepSeek Harness to load this module generation.
- Full suite: **146 / 146 passing**; all-files coverage 85.60% lines / 62.77% branches.
