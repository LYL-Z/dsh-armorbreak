# v1.0.4 — Security Maintenance (Stage A of v1.1.0)

**Release date:** 2026-10-20
**Type:** PATCH / security maintenance
**Baseline:** v1.0.3 (`97d0628`)

本版本只做安全边界修复，不以“功能数量”作为完成标准。对应 v1.1.0 任务书的 Stage A；B–E 阶段（外部工具适配器、DAG 任务、研究工作台 UI）**未实现**。

## 修复

1. **统一研究工具权限边界（P0）**：破甲 preset 不再挂载通用 `tool-fs`/`tool-fs-search`/`tool-pwsh`/`tool-bash`/`tool-web`/`tool-jobs`；新增策略网关内的只读 `armorbreak_files`（list/read/stat/search，有界、无写、无执行）。权限覆盖矩阵见 `docs/security-boundary-review.md`。
2. **授权创建与模型分离（P0）**：`armorbreak_scope` 改为 `request`（仅登记申请）→ 平台审批 → `activate`（记录 approvalSource/approvedBy/approvalId）。移除模型可直接调用的 `authorize`；无审批服务时 fail-closed。
3. **网络探测边界（P0）**：`live.http_probe` 改为流式有界读取、策略期解析并固定 IP、不跟随重定向、超时/Abort 传导、敏感头脱敏；拒绝云元数据地址。
4. **L1 容器执行约束（P0，部分验证）**：镜像必须 digest-pinned 且在 allowlist；`--pull never`、非 root 用户、tmpfs 限制、唯一容器名、超时清理；真实容器成功路径因本机 Docker daemon 不可用而未验证。
5. **文件路径形式（P0）**：拒绝 UNC/设备路径/NUL，保留 realpath 与敏感路径校验。
6. **状态接口（P0）**：`/armorbreak/state` 仅 loopback、仅 GET/HEAD、拒绝 `workspace` 参数，只返回 MRU 工作区的脱敏快照。

## 测试

- 新增 `tests/security-boundary.test.mjs`（7 个测试）：preset 组成、授权分离、UNC/设备路径、受控文件读取、HTTP 固定 IP/不跟随重定向/流式截断、容器镜像与 argv、状态路由访问控制。
- 全套 **153/153 通过**（v1.0.3 的 146 个测试全部保留，新增 7 个）。
- 未执行/未验证：真实 Docker 容器成功路径、模型驱动桌面 GUI E2E、Windows GUI 授权弹窗交互、非 loopback 部署。

## 兼容性

- 工具清单 8 → 9（新增 `armorbreak_files`）；`armorbreak_scope action=authorize` 移除。
- 状态路由不再接受 `?workspace=`。
- 数据 schema 未破坏；升级/回滚见 `docs/migration-v1.0.3-to-v1.1.0.md`。
