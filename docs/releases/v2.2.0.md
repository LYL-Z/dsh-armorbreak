# ArmorBreak V2.2.0 Stable — Verified Core / Experimental Provider Integrations

This version is published only after the separate V2.2 Stable Gate succeeds for the exact `main` source commit, GitHub CI, portable archive, SBOM, and GitHub OIDC/Sigstore attestation. The tag, source SHA, archive SHA-256, SBOM SHA-256, and attestation are listed on the GitHub Release page and in its attached checksum file.

## Included scope

- Universal Core, MCP server, Skills, Offline Golden checks, and recorded local-model verification.
- Only host and installer/migration/rollback paths that are explicitly represented by current compatibility evidence.
- Windows and Ubuntu/Linux CI, Docker L1 integration, release evidence checks, content-inventory SBOM verification, and exact-source build provenance.

## Provider status

OpenAI-compatible, OpenAI Responses, Anthropic Messages, and Gemini Native remain **Experimental Provider Integrations** with status `LIVE_UNVERIFIED`. Protocol adapters and mock/offline tests are available; no claim of official commercial endpoint certification is made. Ollama/local-model evidence applies only to the recorded local environment.

## Security and provenance disclosure

The project recognizes genuine independent AI reviewer reports as **AI-assisted security review**. They are not human audits or third-party security certifications. Targeted regression results apply only to the commit named in each report. GitHub OIDC/Sigstore evidence verifies build origin and artifact subject binding; it does not certify software safety or act as a production code signature.

Stable publication does not change the historical Full GA contract. The legacy readiness remains `gaReady:false` until its own requirements are met; Stable must not be described as Full GA.

## Upgrade and rollback

Before upgrade, back up the DSH profile, ArmorBreak state, workspaces, migration manifests, and reports. Follow [the V2 upgrade and rollback guide](../v2/release/upgrade-guide.md). Verify the release asset against the published SHA-256 list and its GitHub attestation before extracting or installing it. Keep migration manifests and backups until the upgraded workspace is confirmed; use the documented rollback path instead of deleting or rewriting evidence files.
