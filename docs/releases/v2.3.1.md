# ArmorBreak 2.3.1 Stable — release candidate

**Status: NOT RELEASED.** This document describes the proposed repair release. Do not treat it as a published release until the exact `v2.3.1` Tag Gate succeeds and the public GitHub Release assets have been independently downloaded and verified.

## Why 2.3.1

The protected `v2.3.0` Tag remains unchanged. Its Tag Gate failed twice in the Windows deployment/rollback job. Both retained GitHub job logs stop at a combined task/report assertion which did not preserve the individual CLI exit codes or stderr. Those historical runs therefore establish the failure location, but not whether task status or report reading failed. The 2.3.1 candidate adds separately redacted diagnostics and runs the real package drill during PR and exact-main validation, before a new immutable Tag is permitted.

## Scope

- V2.2 task status and report reads are diagnosed independently, including task ID format, task/report metadata, file size and SHA-256, Windows file identity (`dev`, `ino`, `nlink`), normalized path relationship, runner versions, temporary-directory configuration, and ACL summary.
- A failed run writes a structured diagnostic file and uploads it with `if: always()`.
- PR validation exercises a real isolated V2.2 package, the exact PR candidate archive, failure injection, historical task/report reads, and rollback hash comparison.
- The exact-main workflow rebuilds and attests the candidate, then performs the same real Windows deployment/rollback before a release Tag can be created.
- Tag verification uses only the already successful exact-main package, Windows rollback, SBOM, and attestations. It does not rerun the late Windows deployment test.

## Review and support boundaries

The owner has accepted the previously documented implementer AI self-review path. No independent human security audit, independent legal opinion, or maintainer cryptographic signature is claimed. This release does not add an OS-integrated installer/updater or multi-account Windows isolation support. The existing `v2.3.0` Tag and failed Actions runs remain historical records.

## Verification

This candidate note is not evidence of a successful build, CI run, Windows drill, Tag Gate, asset upload, or public Release. Those results must bind to the final exact-main SHA and be recorded in the final release report after they actually occur.
