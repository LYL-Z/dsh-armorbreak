# AB2-M1-04 授权身份/目标绑定

## 已实现

- `ApprovalAuthority`：Host 本地 32-byte HMAC key（`stateRoot/approval.key`，尽力 0600），token 绑定 `id/riskLevel/taskId/target/operator/sessionId/issuedAt/expiresAt/nonce`。
- 签名校验、过期、撤销、nonce 单次消费；重放返回 `TOKEN_REPLAYED`，跨任务/目标返回 `TOKEN_BINDING_MISMATCH`。
- `ScopePolicy` 在启用 authority 时：
  - `source=platform` 的 approval 必须带 token，否则拒绝；
  - `isApprovalActive` 重新验签并检查过期/used；
  - `consumeApproval` 调用 authority.consume，二次消费被拒绝。
- Runner 只有在平台返回 `allowed-once` 之后才签发 token；L1/L2 approval 记录带 token；L1 执行成功后 consume。
- 保留 `source=test` 的本地单元测试兼容路径（不用于生产 runner），已记录为测试后门而非安全边界。

## 测试

- `tests/approval-authority.test.mjs`：签名/绑定/篡改/过期/撤销/重放。
- `tests/approval-binding.test.mjs`：runtime+scope 集成，平台审批无 token 拒绝、跨任务/目标拒绝、消费后重放拒绝。
- 现有 runner-gates/core-policy 回归通过。

## 未完成 / 残余

- 本地拥有 `approval.key` 写权限的用户仍可伪造；这是文档化的剩余风险，不宣称绝对防伪造。
- `armorbreak_scope` 的 authorization 激活仍使用平台回调 + 本地哈希签名，尚未复用 ApprovalAuthority token；授权记录与 approval token 的统一是后续加固项。
- 模型工具仍通过 `armorbreak_scope` 触发平台询问；没有模型可自行铸造 token 的路径，但 PolicyGateway 尚未接到该工具入口（M1-03 REVIEW 项）。
