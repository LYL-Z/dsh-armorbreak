# AB2-M1-04 授权身份/目标绑定（DONE）

## 实现

- `ApprovalAuthority`：Host 本地 32-byte HMAC key（`stateRoot/approval.key`，尽力 0600），token 绑定 id/risk/task/target/operator/session/issuedAt/expiresAt/nonce。
- 签名、过期、撤销、单次消费；跨任务/目标/操作者拒绝；重放拒绝。
- `ScopePolicy`：
  - 平台 approval 无 token 拒绝；复用验签；consume 后再用拒绝。
  - **authorization 激活也要求 Host token**：`armorbreak_scope` activate 通过平台审批后签发 token，`activateAuthorization` 验签并 consume；无 token 或重放拒绝。
- Runner 只在平台 allowed-once 后签发 approval token；L1/L2 执行后 consume。

## 测试

- `tests/approval-authority.test.mjs`：签名/绑定/篡改/过期/撤销/重放。
- `tests/approval-binding.test.mjs`：无 token 拒绝、跨任务/目标拒绝、消费重放拒绝、authorization 激活 token 单次消费。
- `tests/core-policy.test.mjs`：保留无 authority 的纯 ScopePolicy 单元行为。
- 全量回归通过。

## 残余风险

- 本地拥有 `approval.key` 写权限的用户仍可伪造；这是文档化剩余风险，不宣称绝对防伪造。
- 模型不能读取 key 或直接调用 `activateAuthorization`；所有模型路径均需平台 approvalBridge。
- 授权/审批记录的远端签名/外部见证未实现（不在 M1 范围）。
