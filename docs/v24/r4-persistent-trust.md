# Local persistent plugin trust (synthetic staging only)

Trusted host code imports `dsh-armorbreak/plugin-trust-store`. `createPersistentPluginReviewer({directory, policy, policyPublicKey})` creates a new directory, never overwrites an existing store. `openPersistentPluginReviewer({directory, policyPublicKey, minimumSequence})` reopens it. The pinned Ed25519 policy issuer is supplied by trusted host configuration, never by plugin metadata, model input, MCP or the panel.

The signed policy envelope has `payload` and base64 `signature`. Payload schema is `armorbreak.plugin-trust-policy/v1`, with policyId, increasing integer version, notBefore/expiresAt in Unix milliseconds and scoped roots using the existing independent reviewer format. Sign exactly canonicalConfig(payload). A policy issuer key cannot double as an attester root. Rotation requires a valid new signature, same policyId, a strictly higher version and a current validity interval. Old/repeated versions fail. Receipt roles and repositories remain independently checked; distinct authority labels still do not establish actual independent people or organizations. Legal title and GitHub server authentication are not established.

Key/authority revocation appends and fsyncs a bounded local hash-chain journal. Revoked key material remains blocked even if renamed in a newer signed policy. All open reviewer instances reread the current journal. A process rejects truncation below its previously observed tip; on restart the trusted caller can supply its independently retained minimumSequence. This floor must not be taken from candidate input or the journal being checked. Without an external retained floor, a fresh process cannot detect rollback of the entire local history. Hash chaining is corruption detection, not authentication against an OS account capable of rewriting every file. No OS-owner rollback resistance, externally verified authority identity, secure hardware witness or power-loss recovery is claimed.

Synthetic selector commits and public selected-byte reads hold the same exclusive operation lease as policy mutations. A competing mutation returns PLUGIN_POLICY_BUSY and has NOT completed: the caller must retry. No revocation is silently queued or reported successful. Completed revocations are checked by later selections. The lease currently spans host approval; a host must handle busy/cancellation and avoid indefinitely pending approvals. A crashed lease is not automatically cleared. Partial/corrupt journals fail closed and require a separate trusted recovery procedure; no force-reset API exists.

Available methods: review, checkpoint, exportRevocations, revokeKey, revokeAuthority, rotatePolicy and withCommitLease (trusted host composition only). Actual tests use ephemeral synthetic issuer/attester keys and real child processes for persistence and commit contention. No production key or issuer is configured. The isolated store never loads plugin JavaScript, never accepts an existing destination and has no production installation or activation permission.
