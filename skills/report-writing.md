# 安全研究报告规范（ArmorBreak）

## 报告结构
1. **摘要**：目标、范围、结论（按严重程度计数）、覆盖与未覆盖。
2. **授权与范围**：任务工作区、授权记录 id（`armorbreak_scope`）、平台审批 id；没有授权时明确写出「仅限工作区内离线分析」。
3. **任务与工作流**：状态轨迹、每个步骤的能力 id、耗时、结果摘要、失败原因。
4. **发现**：每条必须包含
   - 唯一 id 与标题
   - 位置（文件/偏移/组件/URI/会话）
   - 严重程度 + 评分依据（CVSS 或映射说明）
   - 验证状态（observed/corroborated/hypothesis/unverified）
   - 检测方法与能力 id
   - 证据引用（evidence id + 目标 SHA-256）
   - 影响、修复建议、复测建议
   - 适用条件与不确定性
5. **证据附录**：证据 id、类型、目标哈希、脱敏摘录；证据链与审计链校验结果。
6. **复现条件与限制**：环境、工具、参数、截断、未安装的外部工具、未执行动态分析的原因。

## 写作规则
- 报告中的每条断言都要能追溯到 evidence id；没有证据的结论写进「待验证假设」。
- 扫描器告警不得写成「已确认漏洞」；启发式结论必须标注 verification。
- 不写入原始凭据、Cookie、私钥；摘录脱敏（`[REDACTED]`）。
- 不确定性用明确句式：「在 X 条件下可复现；未验证 Y」。
- 报告格式：`armorbreak_report` 支持 markdown/html/json/sarif/pdf；PDF 需要 LibreOffice，缺失时提供其他格式并说明原因。

## 严重程度参考
- critical：可直接导致未授权代码执行/大规模数据泄露且已有证据。
- high：高影响且路径较清晰（如 exported 组件无保护 + 敏感数据；明文凭据）。
- medium：需要额外条件或影响有限。
- low：加固/信息暴露类。
- info：结构性事实，无直接风险。
