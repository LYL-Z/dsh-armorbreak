# F-03 trusted gate candidate (not deployed)

The existing PR35 worker is useful but not an independent trust root. A PR can rewrite its workflow, tests and validator and report a same-name green check. Required check names alone, even bound to GitHub Actions app 15368, do not identify the reviewed workflow. A same-repository PR may request token permissions; do not grant App credentials to it.

This candidate adds a controller intended for a separate owner-controlled service/host, running a reviewed immutable checkout. It never imports, checks out, builds or executes PR contents. It reads GitHub source-tree identities and actual run/job metadata; it rejects changes/additions/deletions to the frozen control/test/manifest surface. Only narrowly selected product source paths may change without a policy promotion. Tests, workflows, scripts, package/lock files and the controller itself require a separately reviewed policy promotion. False-green same-name checks from PR workflows cannot satisfy a required check bound to the independent App ID.

Keep PR35 at its four-file diff. This PR is stacked on PR35 and adds controller/evaluator/tests/docs only. No protection or published assets change. Candidate approval must not auto-promote policy. Trust policy is generated offline from a reviewed immutable source commit and deployed outside candidate checkouts. Bootstrapping or changing policy requires owner authorization plus ChatGPT review; keep existing one-review enforcement until the trusted App is actually installed and verified.

## Deployment contract / incomplete integration

GitHub repository is public under personal account LYL-Z, admin API available. Account plan API did not disclose a paid plan. Organization-level required workflows are not assumed available. Personal GitHub Apps are supported by GitHub; no functioning independent App installation/key/service has been provisioned in this task. A PAT query to the installation endpoint returned its actual error in evidence; that does not prove no other App exists. This code is a candidate evaluator/CLI, not a deployed automatic webhook service. F03 remains OPEN until installation, trusted hosting and required-source binding are proven.

Provision an owner-controlled App with contents/actions/pull_requests read and checks write, no contents write or administration permission; install only on this repository. Keep key/installation token only in isolated controller hosting. Candidate pull_request workers keep read-only checkout, persist-credentials false (PR35 currently needs follow-up hardening for credential persistence), no repository secrets and no shared trusted caches. Do not run candidates under pull_request_target. Independent controller checks current PR HEAD twice, exact workflow ID/path/repository/run attempt, seven required job names and executed steps, plus tree against external frozen policy. Policy and service deployment are not PR-editable. GitHub required context must bind `ArmorBreak trusted development gate` to the real independent App ID, never Actions or any-source.

Worker GitHub-hosted runner executes untrusted runtime code with no App credential. Controller uses only GitHub API metadata, not logs, artifacts or candidate-reported success files. Product tests are finite evidence, not a proof against arbitrary runtime deception; trusted external integration tests should grow as product APIs evolve. Tree pinning prevents changing test/control definitions; changes to those definitions fail closed until separately promoted. Runtime compromise of GitHub itself, trusted host or App key is outside this mechanism's guarantee.

Operator invocation from the separately trusted checkout: `node tools/trusted-gate/controller.mjs /trusted/policy.json PR_NUMBER RUN_ID --dry-run`. Default is read-only; `--publish` is owner-deployment-only and needs independent App identity. Tokens are taken from ARMORBREAK_CONTROLLER_TOKEN without logging. Use per-request timeout. No candidate-provided policy paths or CLI parameters may reach the service. Webhook automation requires HMAC authentication, delivery deduplication, repository/install allowlist and periodic resync for missed events; not implemented in this candidate. A scheduled owner-controlled poller can invoke the CLI without exposing a network listener.

Required worker changes that alter permissions/checkout settings must be a separate reviewed follow-up PR; do not expand PR35 silently. After review, generate/pin the updated policy and revalidate originals. A new successful source SHA must never reuse an earlier run. Merge-result SHA must also be checked in a separately authorized integration/main run; this candidate validates PR HEAD only.
